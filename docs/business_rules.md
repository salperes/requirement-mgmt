# Business Rules (RMS)

## Global
- UUID primary keys for all entities.
- Requirement uses **soft delete** only.
- AuditLog is **append-only** and cannot be modified or deleted via API.

## Requirement Rules
- Create Requirement => automatically create RequirementVersion **v1**.
- Update Requirement => automatically create a new RequirementVersion **v(n+1)**.
- `req_code` is generated by the system and never changes.
- Default list endpoints hide soft-deleted requirements unless `include_deleted=true`.

## Enums
### Discipline
- System, Mechanical, Software, Electronics, Automation, Optics, Other

### Requirement Type
- Functional, Performance, Safety, Security, Regulatory, Interface, Constraint

### Workflow Status (MVP field)
- Draft, Review, Approved, Rejected

## Baseline Rules
- Creating a baseline freezes the **latest version** of each selected requirement.
- Baselines are immutable once created (no add/remove items).
- Export always references a baseline (or explicitly says "unbaselined draft export").

## RBAC Rules (MVP)
- Admin: full access + user/role management
- RequirementOwner: create/update/delete requirements, create baselines, export
- Reviewer: read + export
- Approver: read + export (approval actions implemented in Module-2)
- Viewer: read-only

## Audit Rules
- Every create/update/delete/baseline action writes an AuditLog record.
- Denied RBAC checks write `RBAC_DENY` with reason and permission.
